# 통합 근태 대시보드 (Leave Management) 사용자 매뉴얼

통합 근태 대시보드는 임직원의 출퇴근 시간 및 실시간 근무 상태를 통제하고, 연차/휴가/외근/출장/재택 및 유연근무 시간표 조정을 상신/결재하며, 구글 캘린더 연동을 기반으로 실시간 근태 현황을 추적하는 근로 시간 통제 센터입니다.

---

## 1. 개요 및 권한 정책

*   **메뉴 경로**: 사이드바 ➡️ **오피스 관리** ➡️ **Leave Management (근태 및 휴가)**
*   **주요 역할**: GPS 위치인증 출퇴근 등록, 실시간 일일/주간 근로 시간 타이머 산정, 유연/휴가 기안 결재선 지정 상신 및 결재 처리, 자동 출근 제어, HR 연차 일괄 관리.
*   **권한 요구사항**:
    *   **일반 임직원 (User)**: 출근 및 퇴근 도장 등록, 실시간 타이머 및 근무 현황 조회, 휴가/근태 기안 상신, 결재 진행 상황 추적.
    *   **부서 책임자 (Manager/Admin)**: 일반 권한 포함 + 소속 부하 직원이 상신한 결재 대기 기안건의 심사(승인/반려 및 코멘트 작성).
    *   **HR 총무 담당자 (Admin/HR)**: 매니저 권한 포함 + 전사 임직원 리스트를 조회하여 수동으로 연차 휴가 일수를 부여 및 조정하는 관리 기능 활성화.

## 2. 화면 구성 및 레이블 정의

### 2.1 상단 종합 요약 현황판
*   **휴가 신청**: 본인의 총 휴가, 사용 일수, 잔여 일수/시간을 요약 노출하며, 클릭 시 휴가 신청 폼 모달을 띄웁니다.
*   **근태 관리**: 유연근로, 출장, 외근 등을 기안 신청하는 모달을 엽니다.
*   **결재 대기**: 자신이 결재해야 할 대기 상태 기안이 있는 경우 붉은색 알림 뱃지로 `N건 처리 필요`를 띄우며, 클릭 시 결재함 모달을 호출합니다.

### 2.2 좌측 근무제어 패널
*   **오늘 근무**:
    *   **근무 시간**: 출근 시점부터 실시간 흘러가는 총 업무 시간이 `hh:mm:ss` 형식으로 초 단위 카운트됩니다.
    *   **출근 / 퇴근 버튼**: 위치기반 GPS 동의를 통해 실제 출근 시간을 찍고, 퇴근 시 업무 상태를 완료 처리합니다.
*   **근태 현황**:
    *   이번주 누적 근무시간 대 법정 근로제한 시간(`weekly / limit` - 예: `34h / 40h`)을 그래프 막대로 명시합니다.
    *   누적 및 잔여 근무시간을 가독성 있게 노출합니다.
*   **근무 신청 (근무시간 조정)**: 시차 출퇴근제 등 본인의 요일별 기본 정규 근무 시간표 조정을 신청할 수 있는 상세 폼 팝업 링크입니다.
*   **연장근로 경고**: 이번주 연장 근로가 감지되면 주간 52시간 근로기준법 경고 뱃지를 자동으로 표시합니다.

### 2.3 우측 근태 캘린더 그리드 레이블
| 레이블명 | 형식 | 설명 |
| :--- | :--- | :--- |
| **날짜 뱃지** | `12px` 숫자 | 오늘 날짜는 파란색 둥근 사각형으로 표시하며, 일요일 및 공휴일은 빨간색으로 매핑 |
| **한국 공휴일** | `8px` 빨간 텍스트 | `KOREAN_HOLIDAYS` 사전을 기준으로 삼일절, 추석, 한글날 등 법정 공휴일 텍스트 표기 |
| **승인 근태 뱃지** | `[부서] 사원명` | 승인이 최종 통과된 휴가, 출장, 재택 등의 정보를 부서/이름과 함께 날짜 칸에 뱃지로 렌더링 |

## 3. 세부 기능 및 모달 액션

### 3.1 위치 기반 출근 및 자동 출근 로직
*   **위치 기반 출근**: [출근] 클릭 시 브라우저 지오로케이션(Geolocation) API를 가동하여 사용자의 동의 하에 GPS 위치를 기록하고 출근을 인증합니다.
*   **오전 6시 자동 출근 (Auto Check-In)**: 근태 누락을 예방하기 위해, 오전 6시 이후에 아직 출근 처리가 안 된 상태로 ERP에 접속할 경우, 시스템이 사용자의 위치를 감지하여 자동으로 출근 상태(`autoCheckIn: true`)로 기록합니다.

### 3.2 다단계 결재선 지정 기안 (Apply Modal)
신청서 기안 시, 사용자 본인이 조직 구조에 맞춰 직접 결재자를 순서대로 추가 지정하는 유연 결재선 아키텍처를 제공합니다.
1.  **카테고리 선택**: `Leave`(휴가), `Flex`(유연근로/시차출퇴근), `Outside`(외근/출장/재택), `Standard`(기본 근무제 조정).
2.  **휴가 잔여일 계산기 (Simulator)**: 휴가 카테고리(연차, 시간제, 공가) 선택 시, 신청 기한 대비 차감되는 휴가 일수가 계산되어 **[신청 후 잔여 휴가]** 상태가 실시간으로 시뮬레이션되어 초과 기안을 방지합니다.
3.  **근무시간 조정 빌더**: 월~금 요일 중 스케줄링할 요일들을 선택한 후, 근무 시작 시간, 종료 시간, 휴게시간(분)을 입력하여 요일별 시간표를 가공/기록합니다.
4.  **결재선 구성**: [결재자 추가] 버튼을 클릭해 단계를 늘려가며 직책(예: 팀장, 본부장)과 승인 대상 임직원(`users` 목록 매핑)을 지정해 순차 결재 루프를 형성합니다.

### 3.3 결재 승인 및 반려 (Approvals Modal)
*   **결재함**: 본인이 승인자로 매핑된 대기 기안 목록이 표시됩니다. [승인] 클릭 시 다음 결재선 단계로 넘어가며, [반려] 클릭 시 반려 사유 텍스트 기입 창이 작동해 기안을 최종 거부 처리합니다.
*   **결재내역**: 승인이 완료되어 캘린더에 연동된 전사 임직원의 휴가 이력을 일람표 형태로 스캔합니다.

### 3.4 HR 전용 연차 관리
*   소속 권한이 `admin` 또는 `manager`인 사용자에게 노출되는 전용 창입니다. 대상 사원을 선택한 뒤 부여할 연차 일수를 양수로 입력하여 사원의 사용 가능 연차를 관리자 권한으로 직접 조정합니다.

## 4. 근태 기안 결재 및 연동 흐름 (Workflow)

휴가, 외근, 출장 등의 근태 기안이 상신되어 결재선 단계를 거쳐 최종 승인 및 구글 캘린더에 연동되기까지의 업무 처리 순서는 다음과 같이 작동합니다.

### 4.1 결재 및 캘린더 동기화 흐름도

```mermaid
flowchart TD
    A([근태/휴가 신청 발의]) --> B[기안서 작성 및 결재선 1~N단계 지정]
    B --> C[기안 상신 (결재 대기)]
    
    C --> D{현재 결재자 검토}
    D -->|반려| E[반려 종결 (반려됨)]
    D -->|승인 - 중간 결재| F[CurrentStep 1 증가 ➡️ 다음 결재자 전송]
    F --> D
    
    D -->|승인 - 최종 결재| G[최종 승인 (승인 완료)]
    
    G --> H[Google Calendar API 백그라운드 구동]
    H --> I[사원 구글 캘린더 일정 등록 완료]
    G --> J[ERP 사내 캘린더 뱃지 렌더링]
    G --> K[사용 가능 연차 자동 차감 계산 적용]
    
    E --> L[기안자 알림 및 캘린더 미동기화]
```

### 4.2 단계별 비즈니스 제약 사항 및 입력 조건

*   **위치(GPS) 출근 제어**:
    *   사용자의 브라우저 Geolocation 정보를 기반으로 사내 좌표 반경 500m 이내일 경우에만 출근이 정상 입력됩니다.
    *   오전 6시 자동 출근(`Auto Check-In`) 발생 시 `autoCheckIn: true` 필드가 주입되어 사용자가 직접 누른 것과 구별할 수 있게 로그화됩니다.
*   **휴가 신청 시뮬레이션 제약**:
    *   신청 일수가 잔여 연차를 초과할 경우, 신청 모달의 '신청 완료' 버튼이 비활성화되며 **"잔여 연차가 부족하여 신청할 수 없습니다."**라는 문구가 노출됩니다.
*   **결재 반려 처리**:
    *   결재자가 [반려] 클릭 시 반드시 **5자 이상의 반려 사유(Comment)**를 기입해야만 반려 처리가 완료됩니다.

## 5. 데이터 연동 및 DB 매핑 정보

### 5.1 파이어베이스 및 외부 API 매핑 구조
*   **출퇴근 일지 DB**:
    *   Firestore 내 `daily_attendance` 컬렉션에 누적됩니다.
    *   문서 ID는 `{user_uid}_{YYYY-MM-DD}` 구조로 고정되어 하루에 1개 문서만 매핑 생성됩니다.
    *   **저장 정보**: `userId`, `userName`, `date` (날짜 문자열), `checkIn` (서버 타임스탬프), `checkOut` (서버 타임스탬프), `autoCheckIn` (Boolean).
*   **기안 문서 DB**:
    *   Firestore 내 `attendance_requests` 컬렉션을 참조합니다.
    *   **저장 정보**: `category`, `type` (상세 분류명), `title`, `userId`, `userName`, `department`, `startDate`, `endDate`, `startTime`, `endTime`, `totalDays` (총 신청 일수), `reason` (사유), `Status` (`Pending` (결재 대기) ➡️ `Approved` (승인 완료) / `Rejected` (반려됨)), `CurrentStep` (현재 결재 승인 진행 단계 인덱스), `ApprovalSteps` (결재자 목록 오브젝트 배열), `ApprovalHistory` (단계별 승인/반려 이력 및 의견 피드백 기록).
*   **시스템 알림 DB**:
    *   결재선 상 다음 차례 승인자 및 최종 결정을 통보받을 사원의 `notifications` 컬렉션에 알림 문서를 추가 상신합니다.
*   **구글 캘린더 연동 (Google Calendar API)**:
    *   최종 단계 결재 승인이 완료(`Status === 'Approved'`)되면 백그라운드에서 `calendarService`의 `syncTaskToGoogleCalendar(requestId, data)`가 구동되어 해당 휴가/출장 기간 일정을 구글 캘린더에 실시간 이벤트로 등록합니다.
    *   반려되거나 철회될 경우 `deleteTaskFromGoogleCalendar(requestId)`를 통해 연동된 구글 일정을 동시 삭제합니다.
