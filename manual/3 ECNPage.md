# ECN 결재 시스템 (Engineering Change Notice) 사용자 매뉴얼

ECN 결재 시스템은 설계 변경 및 최초 릴리즈(BOM 수정) 건에 대하여 부서별(연구, 생산, QA, 영업, 대표) 5단계 전자결재선을 운영하고, 승인 완료 시 자동으로 마스터 부품의 리비전 상승 및 BOM 관계를 갱신하는 통합 설계 승인 모듈입니다.

---

## 1. 개요 및 권한 정책

*   **메뉴 경로**: 사이드바 ➡️ **ERP** ➡️ **ECN (ECN 결재 시스템)**
*   **주요 역할**: 5단계 순차 결재 승인/반려, 사양 변경 비교(Field Diff), BOM 변동 비교(BOM Diff), 파생 모델 동기화 여부 검토, ECO 재고 조치 수립.
*   **권한 요구사항**:
    *   **일반 사원 (User/Guest)**: 기안 대기 및 처리 완료 문서 조회, 승인 이력 검토 가능.
    *   **부서별 결재 담당자 (Lead/Manager)**:
        *   1단계 (연구소 담당자): `ENGINEER_LEAD`
        *   2단계 (생산 담당자): `PRODUCTION_MANAGER`
        *   3단계 (QA 담당자): `QA_MANAGER`
        *   4단계 (영업 담당자): `SALES_MANAGER`
        *   5단계 (대표): `CEO`
        *   *특이 사항*: 시스템 유연성을 위해 권한 마스터 우회(`isMaster = true`)가 활성화된 경우 계정 권한 등급과 무관하게 결재 승인이 가능합니다.

## 2. 화면 구성 및 목록 필터링

### 2.1 결재 대기 및 완료 구분 탭
*   **결재 대기함 (PENDING)**: 현재 승인 대기 중이며 본인이 속한 결재 단계의 진행 문서를 표시합니다.
*   **처리 완료함 (HISTORY)**: 최종 승인이 끝났거나 결재 진행 중 반려(`Rejected`) 처리된 종결 문서를 모아봅니다.

### 2.2 검색 및 정렬
*   **통합 검색**: 결재 요청명(Title), 대상 품번, 기안자 이름으로 필터링 조회가 가능합니다.
*   **정렬**: 기안일자(CreatedAt) 또는 처리완료일자(ProcessedAt) 기준으로 오름차순/내림차순 정렬을 지원합니다.

### 2.3 리스트 컬럼 및 레이블 정의
| 레이블명 | 필드 키 | 설명 |
| :--- | :--- | :--- |
| **요청명 (Title)** | `Title` | 설계 변경 또는 초도 배포 건의 제목 |
| **구분** | `Type` | 요청 성격 (예: `Initial Release`(최초 배포), `ECN`(설계변경)) |
| **품번 (Part ID)** | `PartID` | 변경 대상 마스터 품번 |
| **품명 (Name)** | `PartName` | 변경 대상 마스터 품명 |
| **상태 (Status)** | `Status` | 전체 결재 문서 상태 (`Pending`(결재 진행 중) / `Approved`(승인 완료) / `Rejected`(반려됨)) |
| **결재 현황** | `CurrentStep` | 5개 부서별 진행 막대그래프 뱃지 |
| **기안자** | `RequestedBy` | ECN 기안을 올린 담당자 이름 |
| **요청/처리 일시** | `CreatedAt`/`ProcessedAt` | 최초 상신일 또는 최종 승인/반려 종결 처리 시각 |

## 3. ECN 결재 상세 정보 및 제어 모달

대기 또는 완료 목록에서 문서를 클릭하면 노출되는 결재 상세 관제 모달 창입니다.

### 3.1 헤더 결재선 타임라인 (Timeline Indicator)
*   1번부터 5번 결재선까지의 아이콘이 타임라인 선으로 연결되어 표시됩니다.
*   **색상 상태**:
    *   **녹색 체크**: 해당 부서 담당자가 승인을 완료함.
    *   **빨간 X**: 해당 부서 담당자가 반려 처리하여 결재가 종결됨.
    *   **파란 펄스(Pulse)**: 현재 대기 중인 단계.
    *   **회색**: 결재 대기 중인 미래 단계.
*   각 노드 밑에 **실제 승인 처리자 성함**이 노출됩니다.

### 3.2 품목 기본 정보 및 리비전 플랜
*   **대상 품목 명칭 & 품번**: 변경 영향을 받는 기준 마스터 데이터 노출.
*   **리비전 변동 (Revision Plan)**:
    *   **Current**: 기안 당시의 버전 (예: `Rev 1.0`).
    *   **Proposed**: 최종 승인 시 자동으로 상승 변경될 타깃 버전 (예: `Rev 1.1`).
*   **기안 정보**: 상신자 및 상세 등록 시간.

### 3.3 변경 사유 및 요청 배경
*   설계 변경을 발의한 근거 및 필요 사유를 명시하는 텍스트 영역입니다.

### 3.4 상세 변경 내역 (Field Diff)
부품 속성 정보의 기안 전/후 값을 테이블 형식으로 직관적으로 대조합니다.
*   **항목(Field)**: 변경된 부품 마스터 속성 (예: 단가, 공급사, 제조업체, 규격 스펙 등).
*   **기존 (Before)**: 수정 전 값 (빨간 취소선 표기).
*   **변경 (After)**: 수정 후 타깃 값 (초록 텍스트 표기).

### 3.5 BOM 구조 변경 내역 (BOM Diff)
BOMTree 상에서 자재 구성이 추가/삭제/변경되었는지 가시적인 카드로 비교 표기합니다.
*   **Removed (적색 마이너스 아이콘)**: 기존 BOM에서 제외시킨 하위 자재 및 소요량 정보.
*   **Added (녹색 플러스 아이콘)**: 새롭게 BOM에 추가 편입된 자재 및 단위 수량 정보.
*   **Existing (회색 연필 아이콘)**: 소요량 수량만 변동되거나 유지된 자재 정보.

### 3.6 파생 모델 연동 검토 (Derivative Models) **[중요 비즈니스 룰]**
*   **영업부서(4단계) 필수 예약 제약**:
    *   BOMPage에서 설계 변경을 진행할 때, 원본 품번에서 복제되어 운영되고 있던 **모든 파생 모델 리스트가 모달 내부에 자동으로 연동 호출**됩니다.
    *   **영업 담당자 승인 시점**에, 리스트에 있는 모든 파생 모델에 대하여 **`진행 (Proceed)` 또는 `미진행 (Skip)` 중 하나를 수동으로 필히 선택**해야 합니다.
    *   만약 단 하나의 파생 모델이라도 `Pending` 상태로 남아있을 시 **최종 승인 처리가 원천 차단(Hard Block)**됩니다.

### 3.7 ECO 추가 옵션 (결재 검토자 전용)
*   **현상 변경 여부 (Status Change)**: 물리적 제품 외관이나 특성 변경이 수반되는지 여부 체크박스.
*   **재고 처리 방식 셀렉터**: 신규 리비전 적용 시점에 기존 구형 재고를 어떻게 처리할 것인지에 대한 현장 가이드를 지정합니다.
    *   `그대로 사용 (Use As Is)`
    *   `자연 소진 후 변경 (Running Change)`
    *   `즉시 변경 (Immediate Change)`
    *   `재작업 (Rework)`
    *   `폐기 (Scrap)`

### 3.8 결재 처리 영역 (결재 차례 대기 중인 경우 활성화)
*   **결재 의견 입력창**: 승인 또는 반려 시 코멘트를 자유롭게 입력합니다.
*   **반려 처리 버튼**: 클릭 시 반려 사유를 다시 묻는 프롬프트가 출력되며, 최종 수락 시 문서 상태가 `Rejected`로 종결됩니다.
*   **승인 완료 버튼**: 현재 단계를 승인하고 다음 결재선으로 문서를 토글합니다.
