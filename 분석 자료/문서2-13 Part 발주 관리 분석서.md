# [문서 2-13] Part 발주 관리 (Purchasing) 분석서

## 1. 발주 관리 기능 개요 및 목적
`PurchasingPage.jsx`는 ERP 시스템 내 구매 부서(Purchasing/Procurement)에서 사용하는 핵심 컴포넌트입니다. 등록된 공급업체(Vendors)에게 특정 부품(Parts)의 납품을 요청(Purchase Order, PO)하고, 해당 자재가 공장에 도착하여 입고, 검수, 적재되기까지의 전 과정을 추적 관리합니다. 

특히 물건이 도착했다고 바로 창고(재고)에 반영되는 것이 아니라, **QA 검사 대기 상태로 이관(Pipeline)**시키는 매우 중요한 품질 관리 연결 고리 역할을 수행합니다.

---

## 2. 대시보드 요약 지표 (Stats)
화면 상단에는 구매 담당자가 현재 대응해야 할 핵심 지표 4가지가 카드 형태로 직관적으로 제공됩니다. (`useMemo`를 통해 상태 갱신 시 실시간 계산)
1. **납기 지연 (Overdue):** 현재일 기준 납기 예정일(`DueDate`)이 지났으나 입고가 완료되지 않은 PO의 건수.
2. **승인 대기 (Pending Approval):** 발주서 결제/승인(PaymentStatus가 'PENDING')이 필요한 건수.
3. **미입고 수량 (Unreceived):** 발주한 총수량(`Qty`) 중 아직 입고되지 않은 잔여 수량.
4. **오늘 입고 예정 (Today Due):** 납기 예정일이 오늘인 PO의 건수.

## 3. 핵심 비즈니스 로직 및 파이프라인

### 3.1. 발주 상태 (Order Status) 생명주기
PO는 다음과 같은 상태(`Status`) 흐름을 가집니다.
- **ORDERING (발주중):** 초기 생성 상태
- **WAITING_DELIVERY (입고대기):** 발주 후 물건을 기다리는 상태
- **WAITING_INSPECTION (검사대기):** 물건이 도착(입고 등록)하여 QA 부서의 검사를 기다리는 상태
- **INSPECTION_COMPLETE (검사완료):** QA 검사를 통과하여 적재(Placement)를 기다리는 상태
- **RECEIVED (완료):** 최종적으로 창고의 랙(Rack)이나 로케이션에 적재되어 재고에 반영된 상태

### 3.2. 입고 처리 시 엄격한 QA 연동 로직 (`ReceivePOModal`)
사용자가 발주 내역에서 **'입고 완료(입고 등록)'** 버튼을 누를 경우, 실재고(Inventory)의 단순 수량 증가로 곧장 끝나지 않고 다음과 같은 엄격한 품질 통제 파이프라인으로 넘어가게 구현되어 있습니다.
1. **QA 검사 자동 요청:** 발주(`purchasing`) 상태를 `WAITING_INSPECTION`으로 변경하고, `receiving` 컬렉션(QA 검수 큐)에 새로운 문서를 자동 생성하여 QA 부서로 품질 검사 태스크를 강제 할당합니다.

### 3.3. 입고 후 최종 적재 처리 (Warehouse Placement 연계)
QA 검사를 무사히 통과한 합격품(`INSPECTION_COMPLETE` 상태)들은 창고의 최종 보관 위치(Bin/Location)에 물리적으로 **적치(Placement)**되어야만 파이프라인이 완전히 종료됩니다. (※ 기존 문서 2-19 내용 통합)
1. **창고 적치 대기열 관리:** QA 합격품만 모여있는 전용 뷰에서 담당자가 특정 보관 로케이션(예: `MAIN-01-A`)을 지정하여 '적재 완료'를 처리합니다.
2. **긴급(Urgent) 투입 시각화:** 발주 시 `Urgent` 플래그가 세팅된 자재는 붉은색 번개 아이콘과 함께 "생산 즉시 투입" 버튼으로 표시되어 가시성을 극대화합니다.
3. **4단계 동시 트랜잭션 마감:** 적재 확정 시 시스템은 ① `inventory` 실재고 증가, ② `transactions` 입고 수불 원장 기록, ③ `receiving` 검수 큐 종료(`PLACEMENT_COMPLETE`), ④ 원본 발주서 최종 상태 마감(`RECEIVED`) 처리를 동시에 수행합니다.

### 3.4. 결제 상태 (Payment Status) 별도 트랙 추적
물건의 입고 및 적재(물류 흐름)와는 **완전히 분리된 별도의 회계 트랙**으로 공급업체 대금 지급 상태를 관리합니다. 부품이 입고되더라도 결제는 재무/구매 담당자의 별도 승인을 거칩니다.
- **PENDING:** 결제 대기 (발주 직후 기본값)
- **INVOICED:** 거래명세서/세금계산서 접수 완료
- **PAID:** 대금 지급 완료 (별도의 '결제 완료 처리' 액션 버튼을 통해서만 전환됨)

## 5. 기능 추가 및 수정/보완 요청사항 (Action Items)

> 본격적인 구매/자재 관리 자동화 및 재무 통제를 위해 시스템에 추가되어야 할 필수 고도화 기능들입니다.

1. **[기능 추가] 발주 전 사전 결재(Approval Workflow) 라인 도입:**
   - **현황:** 현재는 담당자가 발주(PO) 문서를 생성하면 곧바로 `ORDERED` 상태가 되어 효력을 발생합니다.
   - **개선안:** 구매는 회사의 자금이 지출되는 행위이므로, 발주 금액(Threshold)에 따라 구매팀장, 재무팀 등의 결재 라인을 거쳐 승인(Approved)되어야만 최종 발주서가 확정되는 다단계 전자 결재 로직 추가.

2. **[기능 추가] 자동 발주 추천 (Auto MRP / Reorder Point):**
   - **현황:** 구매 담당자가 수동으로 부족한 자재를 파악하여 발주서를 기입합니다.
   - **개선안:** 안전재고(Safety Stock) 미달 품목이나 생산 계획 상 확정된 소요 자재량(BOM Explosion)을 시스템이 자동 계산하여, '발주 필요 목록(Suggested PO)'을 대시보드에 띄워주고 원클릭으로 묶음 발주서를 자동 생성해 주는 기능 추가.

3. **[기능 추가] 공급사 발주서(PDF) 자동 이메일 발송 기능:**
   - **현황:** 시스템 내에서 발주 이력만 기록됩니다.
   - **개선안:** 최종 승인된 발주 건에 대해, 시스템에 등록된 해당 공급사(Supplier)의 담당자 이메일로 회사의 공식 발주서(PDF) 양식을 자동 렌더링하여 직접 메일 발송하는 기능 추가.

4. **[기능 보완] QA 불합격품 반품(RMA) 및 결제 차감 프로세스 연동:**
   - **개선안:** 입고 후 QA 검사에서 불량 판정(Reject)이 났을 때, 해당 불량 수량을 공급사에 즉시 반품(Return) 처리하고, 이에 연동하여 재무팀의 결제(Payment) 시 불량 대금을 자동 차감하거나 보류할 수 있는 디테일한 SCM 로직 보완.
