# ERP 시스템 데이터베이스 설계서 (Database Design Document)

본 문서는 IR_Assistant 프로젝트의 Firestore 데이터베이스 구조와 엔티티 간의 관계를 정의한 설계서입니다.

## 1. 핵심 마스터 데이터 (Master Data)

### 1.1 Parts (부품 마스터)
*   **컬렉션명**: `parts`
*   **설명**: 모든 원자재, 부품, 조립품, 완제품 정보를 저장하는 핵심 컬렉션.
*   **필드 정의**:
    *   `PartID` (String): 최종 품번 (예: `IRMIA0001-1.0`). 리비전이 결합된 형태.
    *   `MasterPartID` (String): 리비전과 무관한 마스터 식별자 (예: `IRMIA0001`).
    *   `Name` (String): 부품명.
    *   `Spec` (String): 상세 규격/사양.
    *   `Category` (String): 대분류 (기구부품, 전자부품, 구매품 등).
    *   `Class` (String): 분류 (Part, Assembly 등).
    *   `PartTypeCode` (String): 타입 코드 (P, S, T 등).
    *   `Rev` (String): 리비전 버전 (1.0, 1.1 등).
    *   `IsLatestRevision` (Boolean): 현재 활성화된 최신 버전 여부.
    *   `Lifecycle` (String): 생애주기 상태 (Draft, Active, ECN Pending, Obsolete).
    *   `UnitPrice` (Number): 예상 단가.
    *   `Currency` (String): 통화 (KRW, USD 등).
    *   `Maker` / `Manufacturer` (String): 제조사/메이커 정보.
    *   `Owner` (String): 담당 부서 (회로, 기구, HW 등).
    *   `Safety` (Map): 인증 정보 (CE, RoHS, UL 등 boolean 값).
    *   `SubstitutePartIDs` (Array): 대체 가능 부품 ID 리스트.
    *   `CustomData` (Map): 사용자 정의 커스텀 필드 값.
    *   `CreatedAt` (ISO String): 등록 일시.

### 1.2 BOM (Bill of Materials)
*   **컬렉션명**: `bom`
*   **설명**: 부품 간의 계층적 포함 관계를 정의.
*   **필드 정의**:
    *   `ParentID` (String): 상위(부모) 부품의 PartID.
    *   `ChildID` (String): 하위(자식) 부품의 PartID.
    *   `Quantity` (Number): 소요량.
    *   `Location` (String): 조립 위치 또는 보관 구역.
    *   `Status` (String): Active, Discontinued 등 상태.

## 2. 물류 및 재고 데이터 (Logistics & Inventory)

### 2.1 Inventory (실시간 재고)
*   **컬렉션명**: `inventory`
*   **설명**: 창고별/부품별 현재고 수량을 실시간으로 관리.
*   **필드 정의**:
    *   `PartID` (String): 부품 식별자.
    *   `OnHand` (Number): 현재고 수량.
    *   `Location` (String): 보관 위치.
    *   `LastUpdated` (Timestamp): 최종 변경 일시.

### 2.2 Transactions (수불 이력)
*   **컬렉션명**: `transactions`
*   **설명**: 모든 재고 변동 내역을 기록하는 Audit Trail.
*   **필드 정의**:
    *   `PartID` (String): 대상 부품 ID.
    *   `Type` (String): 변동 유형 (In: 입고, Out: 출고, Adj: 보정).
    *   `Quantity` (Number): 변동 수량.
    *   `Date` (ISO String): 발생 일자.
    *   `LotNumber` (String): 추적용 LOT 번호.
    *   `Ref` (String): 참조 문서 (PO#, PR# 등).
    *   `Reason` (String): 변동 사유.

### 2.3 Receiving (QA 입고 검사)
*   **컬렉션명**: `receiving`
*   **설명**: 발주/생산 완료 후 QA 검사 대기 및 결과 기록.
*   **필드 정의**:
    *   `RefID` (String): 원천 문서 ID (PO ID 등).
    *   `PartID` (String): 검사 대상 부품.
    *   `Status` (String): Pending, Inspecting, Passed, Failed.
    *   `TestQty` (Number): 검사 수량.
    *   `PassQty` / `FailQty` (Number): 합격/불량 수량.

## 3. 구매 및 생산 데이터 (Purchasing & Production)

### 3.1 Purchase Orders (구매 발주)
*   **컬렉션명**: `purchase_orders`
*   **필드**: `PONumber`, `VendorID`, `PartID`, `Qty`, `UnitPrice`, `Status` (Open, Closed), `DueDate`.

### 3.2 Production Requests (생산 의뢰)
*   **컬렉션명**: `production_requests`
*   **필드**: `PRNumber`, `CustomerID`, `PartID`, `TargetQty`, `Status` (Wait, Production, Finished), `DueDate`.

### 3.3 Outsourcing (외주 관리)
*   **컬렉션명**: `outsourcing`
*   **필드**: `OSNumber`, `VendorID`, `ProcessType`, `Qty`, `Status`, `CreatedAt`.

## 4. 운영 및 설정 데이터 (System & Settings)

### 4.1 ECN (설계 변경)
*   **컬렉션명**: `ecns`
*   **필드**: `PartID`, `Title`, `Reason`, `Changes` (Map), `ApprovalHistory` (Array), `Status` (Pending, Approved, Rejected), `CurrentStep`.

### 4.2 Metadata & Fields
*   **컬렉션명**: `metadata`, `metadata_fields`, `part_counters`
*   **설명**: 시스템 옵션 리스트, 동적 필드 정의, 자동 채번용 카운터 관리.

## 5. 데이터 관계도 (ERD 개요)

1.  **Parts (1) : (N) BOM**: 한 부품은 여러 하위 부품을 가질 수 있고, 여러 상위 부품에 속할 수 있음.
2.  **Parts (1) : (1) Inventory**: 부품당 하나의 실시간 재고 레코드 존재.
3.  **Parts (1) : (N) Transactions**: 부품 한 개에 대해 수많은 입출고 기록 발생.
4.  **Production Request (1) : (N) Transactions**: 생산 완료 시 BOM 기반 자재 자동 출고(Backflushing) 처리.
5.  **ECN (1) : (1) Parts**: ECN 승인 시 신규 Revision 부품 생성.
