# ERP 시스템 상세 기능 명세서 (Functional Specification)

본 문서는 IR_Assistant 프로젝트의 소스 코드 분석을 바탕으로 작성된 ERP 시스템의 상세 기능 명세서입니다.

---

## 1. 탭별(메뉴별) 상세 기능

### 1.1 부품 관리 (Part List)
*   **핵심 목적**: 시스템에서 사용하는 모든 원자재, 부품, 조립품, 완제품의 마스터 데이터를 관리.
*   **주요 기능**:
    *   **부품 등록 및 수정**: 카테고리, 분류, 타입코드에 따른 Part ID 자동 생성.
    *   **리비전 관리**: 부품 변경 시 Minor Revision(1.0 -> 1.1) 관리 및 히스토리 보존.
    *   **커스텀 필드**: 모듈별 동적 필드(Material, Grade, Color 등) 추가 및 관리.
    *   **Lifecycle 상태**: Draft(개발), Active(양산), ECN Pending(수정중), Obsolete(단종) 상태 제어.
*   **주요 데이터 엔티티**: Part (ID, Name, Spec, Maker, UnitPrice 등)

### 1.2 BOM 관리 (Bill of Materials)
*   **핵심 목적**: 제품 구성의 계층 구조를 정의하고 자재 소요량을 관리.
*   **주요 기능**:
    *   **계층 구조(Tree) 시각화**: 재귀적 트리 구조를 통한 중첩된 BOM(Multi-level) 조회.
    *   **BOM 편집**: 드래그 앤 드롭 또는 검색을 통한 자식 부품 추가, 수량(Qty), 보관위치 수정.
    *   **Where-Used 분석**: 특정 서브 어셈블리가 어느 상위 제품에서 사용되는지 역추적.
    *   **ECN 연동**: BOM 수정 시 설계변경(ECN) 프로세스와 강제 연동하여 이력 관리.
*   **주요 데이터 엔티티**: BOM (ParentID, ChildID, Quantity, Location)

### 1.3 설계 변경 관리 (ECN)
*   **핵심 목적**: 부품 사양 또는 BOM 구조 변경에 대한 공식적인 승인 절차 수행.
*   **주요 기능**:
    *   **5단계 워크플로우**: 연구소 -> 생산 -> QA -> 영업 -> 대표이사 순차 결재.
    *   **변경 내역 비교(Diff)**: 필드 값 변경 및 BOM 구조 변경(Add/Remove) 내역 시각화.
    *   **자동 마스터 업데이트**: 최종 승인 시 자동으로 기존 부품을 아카이브하고 신규 리비전 부품 생성.
*   **주요 데이터 엔티티**: ECN (Title, Changes, ProposedBOM, ApprovalHistory, Status)

### 1.4 발주 관리 (Purchasing)
*   **핵심 목적**: 외부 공급업체로부터 원자재 및 부품을 구매하는 프로세스 관리.
*   **주요 기능**:
    *   **발주서(PO) 생성**: 공급사별 품목, 리비전, 단가, 납기일 지정.
    *   **물류 상태 추적**: 발주중 -> 입고대기 -> 검사대기(QA) -> 검사완료 -> 적재완료 단계별 관리.
    *   **정산 관리**: 결제대기, 청구됨, 지급완료 상태 관리 및 미정산액 집계.
*   **주요 데이터 엔티티**: Purchasing (PONumber, VendorID, Qty, UnitPrice, Status)

### 1.5 품질 관리 (QA Process)
*   **핵심 목적**: 생산 및 입고 과정에서의 품질 검사 및 사후 관리.
*   **주요 기능**:
    *   **중간/출하 검사**: 공정별 양품/불량 수량 기록 및 불량률 자동 산출.
    *   **AS 관리**: 고객 클레임 접수 및 수리 내역, 비용, 원인 분석(Cause Code).
    *   **불량 코드 체계**: 표준화된 불량 코드를 활용한 품질 데이터 통계화.
*   **주요 데이터 엔티티**: QA Inspection (Model, TestQty, PassQty, FailQty, DefectList)

### 1.6 재고 현황 (Inventory)
*   **핵심 목적**: 창고 내 부품의 실시간 수량 및 가치를 모니터링.
*   **주요 기능**:
    *   **실시간 수량 파악**: 현재고(OnHand) 및 안전재고(Safety Stock) 대비 현황 확인.
    *   **위험 재고 알림**: 안전재고 미만 품목에 대한 자동 경고 및 필터링.
    *   **재고 보정**: 수동 입출고 또는 보정 기능을 통한 재고 동기화.
*   **주요 데이터 엔티티**: Inventory (PartID, OnHand, Location, LastUpdated)

### 1.7 생산 의뢰 (Production Requests)
*   **핵심 목적**: 영업 수주를 기반으로 생산팀에 작업 의뢰를 전달.
*   **주요 기능**:
    *   **자재 가용성 체크(Pre-check)**: 의뢰 전 BOM 기반으로 현재 재고가 충분한지 자동 분석.
    *   **파이프라인 관리**: 수주부터 출하까지 12단계 상태 전이 추적.
    *   **매출 집계**: 수주 기반 예상 매출 데이터를 대시보드와 연동.
*   **주요 데이터 엔티티**: Production Request (PRNumber, CustomerID, TargetQty, DueDate, Status)

### 1.8 생산 실행 (Production Execution)
*   **핵심 목적**: 제조 현장에서의 작업 지시 이행 및 결과 보고.
*   **주요 기능**:
    *   **칸반 보드/스플릿 뷰**: 현장 작업 중심의 시각적 UI 제공.
    *   **Backflushing**: 생산 완료 시 BOM 구조에 따라 원자재 재고를 자동으로 차감(Out) 처리.
    *   **QA 자동 이관**: 생산 완료 즉시 품질 검사 대기열로 데이터 전송.

### 1.9 외주 관리 (Outsourcing)
*   **핵심 목적**: 외부 협력사를 통한 가공 및 조립 공정 관리.
*   **주요 기능**:
    *   **외주 발주(OS)**: 외주 업체별 가공 의뢰서 발행.
    *   **진척률 모니터링**: 업체별 납품 수량 및 납기 준수 현황 시각화.

### 1.10 입출고 관리 (Transactions)
*   **핵심 목적**: 자재 및 완제품의 모든 유입/유출 이력을 추적하고 수불 원장을 관리.
*   **주요 기능**:
    *   **바코드/QR 스캔**: PDA 시뮬레이션을 통한 고속 입출고 등록 및 LOT 번호 자동 생성.
    *   **수불 이력 추적**: 기간별(1주일~3개월) 입출고 현황 필터링 및 엑셀 내보내기.
    *   **Audit Trail**: 데이터 수정 시 전/후 차이(Diff) 기록 및 수정 사유 강제 입력으로 무결성 보장.
    *   **이상 감지**: 마이너스 재고 발생 또는 비권한자 접근 시 관리자 알림 발송.
*   **주요 데이터 엔티티**: Transaction (Type, PartID, Qty, LotNumber, Location, Reason)

### 1.11 통합 대시보드 (Dashboard)
*   **핵심 목적**: 부서별 핵심 지표(KPI) 및 실시간 현황을 한눈에 파악.
*   **주요 기능**:
    *   **위젯 기반 구성**: 근태, 위험 재고(Low Inventory), 내 작업(Tasks), 결재 대기(ECN), 발주 현황 등을 위젯 형태로 배치.
    *   **실시간 요약**: 시스템 전반의 핵심 데이터를 요약하여 실시간 업데이트.

## 2. 부서별 기능 분류

### 2.1 영업 부서 (Sales)
*   **고객 관리**: 신규 고객사 등록 및 거래 이력 확인.
*   **생산 의뢰**: 수주 정보 입력, 자재 부족분 사전 파악, 납기 약속.
*   **출하 이력**: 고객별 납품 데이터 및 관련 품질 성적서 통합 관리.

### 2.2 개발 부서 (R&D / Engineering)
*   **Part 마스터 정의**: 부품 번호(ID) 체계 수립 및 데이터 유지보수.
*   **BOM 설계**: 제품 구성도 작성 및 리비전 관리.
*   **ECN 기안**: 기술 변경 사항에 대한 근거 제시 및 5단계 순차 결재 진행.
*   **제조사 관리**: 승인된 부품 제조사(Maker) 데이터 관리.

### 2.3 QA 부서 (Quality Assurance)
*   **수입 검사**: 구매/외주 입고품에 대한 합격/불합격 판정 및 적재 허용.
*   **공정/출하 검사**: 생산 중간 단계 및 최종 완제품 검사 보고서 작성.
*   **AS/클레임 처리**: 고객 클레임 분석 및 결함 원인(Cause) 데이터화.

### 2.4 생산 부서 (Production / SCM)
*   **재고/창고 관리**: 실시간 재고 파악, 안전재고 유지, 창고 위치별 수불 관리.
*   **발주/구매**: 원자재 구매 발주(PO) 및 납기/미지급금 관리.
*   **생산 실행**: 작업 지시(WO) 발행, 생산 현황 칸반 관리, 자재 자동 차감(Backflushing) 처리.
*   **외주 관리**: 외부 가공 업체 발주 및 진척률 트래킹.

## 3. 데이터 관계 및 비즈니스 프로세스

### 3.1 Part ID 규칙 (Naming Convention)
*   **구조**: `IR` + `Category` + `Class` + `Type` + `Seq(4자)` + `-Rev(선택)`
*   **예시**: `IRMIA0001-1.0`
    *   Category: M(기구), E(전자), O(구매)
    *   Class: I(Part), A(Assembly)
    *   Type: A(Assembly Sub), P(Plastic), S(Sheet Metal) 등

### 3.2 비즈니스 프로세스 흐름
1.  **개발 단계**: Part 등록 -> BOM 구성 -> (필요시) ECN 승인 -> 정식 마스터 확정.
2.  **영업 단계**: 고객 수주 -> 생산 의뢰(PR) 발행 (자재 가용성 체크).
3.  **준비 단계**: 부족 자재에 대한 구매 발주(PO) 또는 외주 발주(OS) -> 자재 입고 및 수입 검사.
4.  **생산 단계**: 작업 지시(WO) -> 생산 실행 -> 완료 시 재고 자동차감(Backflushing).
5.  **출하 단계**: 최종 QA 검사 -> 합격 판정 -> 출하 준비 -> 고객사 납품.
