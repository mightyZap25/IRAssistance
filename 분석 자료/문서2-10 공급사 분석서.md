# [문서 2-10] 공급사 및 외주업체 (Vendors) 분석서

## 1. 페이지 구조 및 매핑 현황 확인
요청하신 사항과 관련하여 두 개의 소스 코드를 확인했습니다.

1. **`src/pages/OutsourcingPage.jsx` (외주 관리 탭):** 현재 시스템 상 하드코딩된 UI 텍스트("페이지 준비 중입니다. 외주 생산 내역을 관리하는 기능이 곧 업데이트될 예정입니다.")만 렌더링하고 있는 플레이스홀더(Placeholder) 상태입니다.
2. **`src/pages/VendorsPage.jsx` (공급업체 관리 탭):** 실제로 외부 공급사(원자재 납품 업체) 및 외주 가공 업체의 마스터 데이터를 관리하는 실질적인 비즈니스 로직이 구현된 곳입니다.

따라서 본 분석서는 실제 데이터가 작동하는 **`VendorsPage.jsx`**를 기준으로 작성되었습니다.

---

## 2. 공급업체(Vendors) 관리 기능 개요 및 목적
`VendorsPage` 컴포넌트는 자사 제품의 원자재를 납품하거나, 1차 가공(외주가공)을 대행해 주는 외부 파트너사들의 마스터 데이터를 관리하는 화면입니다. 주로 구매 부서나 영업 부서(`sales`)에서 사용하며, 추후 발주(PO, Purchase Order) 생성 시 "어떤 업체에게 발주할 것인가"를 선택하는 기준 데이터베이스가 됩니다.

---

## 3. 보기 방식 및 UI 구조
앞서 분석한 고객사(Customers), 제조사(Manufacturers) 화면과 동일한 아키텍처 패턴을 공유합니다.

- **그리드 카드(Grid Card) 뷰:** 화면 크기에 따라 1열에서 3열까지 늘어나는 반응형 카드 리스트 구조입니다.
- **실시간 검색:** 상단 검색바에서 업체명(`Name`) 검색 시 프론트엔드 메모리 상에서 실시간으로 목록이 즉각 필터링됩니다.
- **아이콘 기반 UI:** 각 카드 내부는 `Briefcase`, `User`, `Mail`, `Phone` 등 `lucide-react` 아이콘을 활용해 텍스트 가독성을 높였습니다.

---

## 4. 관리 데이터 구조 (Firestore 스키마)
공급업체 카드는 직관적인 아이콘과 함께 주요 정보를 노출합니다. 소스코드 상 `vendors` 컬렉션에서 다루는 필드는 다음과 같습니다.

### 4.1. 화면 노출 핵심 필드
1. **업체명 (Name):** 카드의 타이틀 (필수값)
2. **유형 (Category):** '부품공급', '외주가공', '기타' 세 가지로 분류되어 배지 형태로 표시됩니다. 이 Category 값을 통해 단순 자재 납품처인지, 외주 생산 파트너인지 식별합니다.
3. **담당자 (Contact Person):** 해당 업체의 실무 담당자명
4. **이메일 (Email):** 담당자의 이메일 연락처
5. **전화번호 (Phone):** 담당자 및 회사의 전화번호

### 4.2. 추가 확장성
등록 모달을 보면 `Address`(주소) 필드도 관리 대상에 포함되어 있으나, 메인 카드 뷰에서는 디자인의 심플함을 위해 생략되어 있습니다.

## 5. 데이터 추가 / 수정 / 삭제 및 이력(Audit Trail) 관리 흐름
- **VendorModal (업체 등록/수정 모달):** 
  - `isModalOpen` 상태에 의해 화면 위에 나타나며, 기존 데이터가 있으면 데이터 수정(Update) 모드, 없으면 신규 생성(Create) 모드로 동작합니다.
- **정보 수정 및 내역 관리 (Revision History):**
  - 거래처의 담당자 연락처, 주소, 특히 결제 조건 등이 변경될 경우 수정 기능을 통해 데이터를 업데이트해야 합니다.
  - 단, 과거 계약서나 견적서와의 정합성을 보장하기 위해 단순 덮어쓰기가 아니라 **수정 내역 관리(Audit Trail)** 로직이 반드시 결합되어야 합니다.
  - 공급사 정보 수정(`updateDoc`) 발생 시 시스템은 내부적으로 `vendor_revisions` (또는 `audit_logs`) 컬렉션에 "누가, 언제, 어떤 항목을 A에서 B로 변경했는지" 변경 전/후 스냅샷 데이터를 자동 기록하도록 설계합니다.
- **Firestore 트랜잭션:**
  - `addDoc` (생성), `updateDoc` (수정), `deleteDoc` (삭제)를 통해 DB를 조작하며, 성공 시 프론트엔드 상태 배열(`setVendors`)을 갱신하여 빠른 UI 피드백을 제공합니다.
