# [문서 2-7] 재고 현황 (Inventory) 분석서

## 1. 재고 관리 기능 개요 및 목적
`InventoryPage` 컴포넌트는 ERP 시스템 내 부품(Part)들의 실시간 창고 보관 상태(현재고, 위치)를 모니터링하는 화면입니다. 생산(`engineer`/`production`) 부서가 조립 전 필요한 자재가 충분한지 파악하거나, 자재관리(창고) 담당자가 재고 부족(Shortage) 상태를 확인하고 발주를 요청하는 등 물류 흐름의 기준점이 되는 핵심 메뉴입니다.

---

## 2. 데이터 병합 (Merge) 및 표시 로직
이 페이지의 가장 큰 기술적 특징은 마스터 데이터베이스와 트랜잭션 결과(재고) 데이터베이스를 프론트엔드 레벨에서 실시간 병합(Merge)하여 보여준다는 점입니다.

- **로직 구조:** 
  1. `parts` 컬렉션에서 부품의 기본 마스터 정보(이름, 단가, 안전재고 등)를 가져옵니다. (`단종(IsDiscontinued)` 부품은 제외)
  2. `inventory` 컬렉션에서 각 부품별 실제 보관 수량(`OnHand`)과 보관 창고 위치(`Location`) 데이터를 가져와 메모리 상의 맵(Map) 객체를 만듭니다.
  3. `PartID`를 키(Key)값으로 사용하여 두 데이터를 하나로 결합한 뒤 화면 테이블에 렌더링합니다.
- **위험 감지 표시:** 현재고(`OnHand`) 수량이 부품 마스터의 안전재고(`SafetyStock`) 수량보다 적을 경우, 테이블의 재고 숫자가 **빨간색(red)**으로 강조 표시되어 직관적으로 재고 부족 위험을 알립니다.

---

## 3. 상세 뷰 및 이력 추적 (InventoryDetail Drawer)
부품 목록에서 특정 행을 클릭하면 `InventoryDetail` 컴포넌트가 대형 모달(Drawer) 형태로 열리며 깊이 있는 분석 데이터를 제공합니다.

### 3.1. 요약 지표 (Stats)
모달 상단에는 현재 해당 부품의 총 재고 수량, 창고 위치, 마스터 단가가 큰 폰트로 강조되어 직관적인 상황 판단을 돕습니다.

### 3.2. 입출고 내역 탭 (History Tab)
- **목적:** 재고가 언제, 어떤 사유로 들어오고 나갔는지(Traceability)를 추적합니다.
- **로직:** `transactions` 컬렉션에서 해당 `PartID`를 가진 최근 50건의 트랜잭션을 날짜순으로 가져옵니다.
- **UI 표시:** 입고(`In`)는 파란색 아이콘과 `+` 수량으로, 출고(`Out`)는 주황색 아이콘과 `-` 수량으로 표시되며, 해당 거래의 참조 번호(`Ref` - 예: 발주번호, PR번호)가 함께 명시됩니다.

### 3.3. BOM 구조 탭 (BOM Tab)
- **목적:** 현재 조회 중인 자재가 조립품(Assembly)일 경우, 어떤 하위 부품들로 구성되어 있는지 재고 화면을 벗어나지 않고 즉시 확인합니다.
- **로직:** `bomService`의 `getBOMStructure` 함수를 호출하여 트리 구조를 만든 뒤 `BOMTree` 컴포넌트를 재사용하여 렌더링합니다.

## 5. 기능 추가 및 수정/보완 요청사항 (Action Items)

> 현재의 단순 재고 열람 및 입출고 내역 조회를 넘어, 실제 창고(Warehouse) 물류 관리에 필요한 고도화 요건입니다.

1. **[기능 추가] 재고 실사(Physical Inventory / Cycle Count) 및 보정 기능:**
   - **현황:** 현재고는 단순히 입출고(Transactions)의 합산으로만 관리됩니다.
   - **개선안:** 주기적인 창고 실사 후, 시스템 재고와 실제 재고 간의 오차(차이 수량)를 입력하면 이를 보정(Adjustment)해주는 전용 트랜잭션을 발생시키고 승인받는 기능 추가.

2. **[기능 추가] 바코드/QR 스캐너 연동 (Barcode/QR Integration):**
   - **현황:** 사용자가 직접 검색창에 품번이나 품명을 입력하여 부품을 찾습니다.
   - **개선안:** 부품 라벨의 바코드나 QR 코드를 스캐너(또는 모바일 기기)로 찍었을 때, 즉시 해당 부품의 `InventoryDetail` 서랍(Drawer)이 열리고 빠른 입/출고 처리가 가능하도록 UI/UX 보완.

3. **[수정/보완] 다중 창고 및 세부 로케이션(Multi-Location/Bin) 관리 강화:**
   - **현황:** 단일 창고 기준으로 위치(Location)만 관리되고 있습니다.
   - **개선안:** 동일한 부품이라도 '자재창고 A구역', '조립 대기 라인 B구역' 등 여러 창고/위치에 분산 보관될 수 있으므로, 재고 상세 내역에서 **위치별(Bin/Location) 재고 수량을 분리해서 표기**할 수 있도록 DB 및 화면 구조 보완.

4. **[수정/보완] 로트(LOT) 및 시리얼 번호(Serial Number) 추적:**
   - **현황:** 품목 단위의 총 수량(Qty)만 보여줍니다.
   - **개선안:** 제품 불량 발생 시 추적성(Traceability)을 확보하기 위해, 입고 시 부여된 LOT 번호나 시리얼 번호 단위로 재고를 분할 관리하고 조회할 수 있는 체계 도입 필요.
