# [문서 2-8] 칸반(Kanban) 페이지 분석서

## 1. 생산 계획(Kanban) 기능 개요 및 목적
`KanbanPage` 컴포넌트는 생산 부서나 개발 부서에서 진행 중인 업무(Issue, Task)와 생산 스케줄을 애자일(Agile) 방식으로 관리할 수 있는 드래그 앤 드롭(Drag & Drop) 보드입니다. `프로젝트(Project)` 단위로 워크스페이스가 나뉘며, 각 프로젝트 내에서 커스텀 가능한 상태 컬럼(To Do, In Progress, Done 등)을 통해 작업 카드의 상태를 직관적으로 추적하고 변경할 수 있습니다.

---

## 2. 사용 라이브러리 및 핵심 아키텍처
최신 React 트렌드에 맞게 복잡한 드래그 앤 드롭 로직을 처리하기 위해 `@dnd-kit` 라이브러리가 적극 활용되었습니다.

- **DND Kit 구성요소:**
  - `<DndContext>`: 드래그 앤 드롭의 전체 영역을 감싸며 센서(마우스, 키보드) 이벤트와 충돌 감지(`closestCorners`)를 제어합니다.
  - `<DragOverlay>`: 카드를 집어서(Drag) 이동할 때 화면 위에 반투명하게 떠다니는 시각적 효과(잔상)를 부드럽게 렌더링합니다.
- **실시간 동기화 (onSnapshot):** 프로젝트, 이슈(카드), 사용자, 부품 리스트를 가져올 때 `getDocs` 대신 `onSnapshot` 리스너를 사용하여 다른 사용자가 카드를 이동시키거나 생성하면 내 화면에도 새로고침 없이 즉각(Real-time) 반영됩니다.

---

## 3. 데이터 구조 및 관계 (Firestore)
이 화면은 복합적인 컬렉션 조인(Join)을 프론트엔드에서 수행합니다.

1. **Projects (`projects` 컬렉션):**
   - 최상위 컨테이너입니다. 각 프로젝트 문서는 하위에 어떤 컬럼(`columns`: id, title, color)들을 가질지 정의하고 있습니다.
   - 드롭다운을 통해 프로젝트를 전환하면 화면의 칸반 보드가 해당 프로젝트에 맞게 리렌더링됩니다.
2. **Issues / Tasks (`issues` 컬렉션):**
   - 칸반 보드에 올라가는 개별 '카드'입니다.
   - `projectId` 속성으로 자신이 속한 프로젝트를 식별하고, `columnId` 속성으로 현재 자신이 어떤 상태(열)에 있는지 기억합니다.
3. **Users & Parts:**
   - 카드의 담당자(`assignedTo`)를 표시하기 위해 `users` 컬렉션을, 카드에 연관된 부품 스펙을 연결하기 위해 `parts` 컬렉션을 참조(Lookup)하여 카드 데이터를 풍부(Enrich)하게 만듭니다.

---

## 4. 핵심 동작 흐름 (Drag & Drop)
사용자가 카드를 마우스로 집어 다른 컬럼으로 옮길 때 발생하는 로직(`handleDragEnd`)은 다음과 같습니다.

1. **대상 식별:** 드래그가 끝나는 순간(Drop), 사용자가 놓은 위치의 대상 요소(`over.id`)가 무엇인지(비어있는 컬럼인지, 아니면 다른 카드 위인지) 파악합니다.
2. **새로운 Column ID 추출:** 놓여진 대상이 특정 카드라면 해당 카드의 `columnId`를, 컬럼 자체라면 해당 컬럼의 `id`를 `newColumnId`로 설정합니다.
3. **Firestore 업데이트:** 기존 카드의 `columnId`와 `newColumnId`가 다르다면(상태가 변경되었다면), 즉시 `updateIssue(issueId, { columnId: newColumnId })`를 호출하여 DB를 업데이트합니다.
4. **UI 반영:** DB가 업데이트되면 `onSnapshot` 리스너가 이를 감지하여 모든 접속자의 화면에서 카드가 새 컬럼으로 이동합니다.
