# 프론트엔드 공통 컴포넌트(Common Component) 정의서

문서 2-1부터 2-17까지의 ERP 세부 기획을 분석하여, **반복적으로 사용되는 UI와 기능을 추출한 '공통 컴포넌트 라이브러리' 정의서**입니다. 본 컴포넌트들은 여러 페이지에서 `import`하여 재사용되며, 각 컴포넌트가 가지는 고유의 레이블(Label)과 세부 기능을 정의합니다.

---

## 1. 상세 정보 패널 컴포넌트 (Detail View Panels)

### 1.1. `<PartDetailPanel />` (부품 상세 뷰)
- **사용처:** 재고 현황(2-7), 부품 마스터(2-1), 발주 관리(2-13), 생산 의뢰(2-12)
- **주요 레이블 및 필드:**
  - `Part ID`, `부품명(Description)`, `카테고리(Category)`, `규격(Specification)`
  - `리비전(Revision No - ※ 자체 제조/조립품의 경우 도면 및 스펙 변경 이력 관리를 위해 필수 표기)`
  - `현재고(On-hand Qty)`, `안전재고(Safety Stock)`, `표준 원가(Standard Cost)`
  - `제조사(Manufacturer)`, `대체품 목록(Substitutes)`
- **핵심 기능:**
  - **이미지 뷰어:** 썸네일 클릭 시 확대된 원본 도면/사진 모달 오픈.
  - **대체품 네비게이션:** 대체품 목록 클릭 시, 현재 뷰를 해당 대체품의 패널로 전환(라우팅).
  - **내부 탭 분리:** [기본 정보] / [최근 입출고 이력] / [BOM Where-used] 탭으로 화면 분할.

### 1.2. `<BOMDetailPanel />` (BOM 상세 뷰)
- **사용처:** BOM 관리(2-2), 생산 의뢰(2-12), ECN(2-5)
- **주요 레이블 및 필드:**
  - `최상위 조립품명(Top-Level Assy)`, `리비전 번호(Revision No)`, `작성일/승인자`
  - `Level(레벨)`, `소요 수량(QPA)`, `자재 단가 합산액(Total Cost)`
- **핵심 기능:**
  - **리비전 롤백/비교:** 과거 리비전(버전)을 선택하면 현재 버전과의 차이점(추가/삭제된 자재)을 하이라이팅하여 표시.

### 1.3. `<VendorDetailPanel />` (공급사 상세 뷰)
- **사용처:** 공급사(2-10/2-18), 정산 관리(2-16)
- **주요 레이블 및 필드:**
  - `업체명`, `사업자등록번호`, `대표 연락처`, `영업 담당자 이메일`
  - `결제 조건(Payment Terms - 예: 익월 말 현금)`, `여신 한도(Credit Line)`
  - `품질 등급(Vendor Score - S/A/B/C)`
- **핵심 기능:**
  - **이메일 원클릭 발송:** 담당자 이메일 레이블 클릭 시 시스템 내에서 메일 작성 팝업 활성화.
  - **단가 이력 차트:** 특정 자재에 대해 해당 업체가 과거에 제시했던 견적 단가 변동 추이를 미니 차트로 렌더링.

## 2. 그리드 및 테이블 컴포넌트 (Data Grids & Tables)

### 2.1. `<MasterDataGrid />` (마스터 데이터 전용 그리드)
- **사용처:** 부품 마스터(2-1), 제조사(2-9), 고객사(2-3), 공급사(2-10) 등 마스터 데이터 조회 화면 전체
- **주요 레이블 및 구성요소:**
  - 좌측 상단: `총 N건 조회` 수치 표시
  - 우측 상단: `[표시 열 설정]` 기어 버튼 (출력 열 순서 드래그 정렬 및 가시성 토글 드롭다운 내장)
  - 컬럼 헤더: 정렬 아이콘(▲/▼)을 포함한 Sticky Header
  - Row 액션: 우측 정렬된 관리 열 내 `[수정]`, `[삭제]` 아이콘 버튼
- **핵심 기능:**
  - **드래그 앤 드롭 열 정렬 (Drag & Drop Column Reordering):** `@dnd-kit/sortable` 라이브러리를 활용하여 사용자가 표시 열 설정 팝업에서 열 레이블을 드래그하여 임의로 열의 순서를 바꿀 수 있으며, 배경 테이블의 열 순서가 즉시 동기화됩니다.
  - **커스텀 셀 렌더러 (Custom Cell Renderers):** `cellRenderer` Props를 통해 특정 열(예: Category 뱃지, Lifecycle 상태 뱃지, UnitPrice 달러 콤마 처리 등)의 렌더링 함수를 주입받아 유연하고 다채로운 셀 커스터마이징을 제공합니다.
  - **반응형 패딩 및 불투명 Sticky 헤더:** 테이블이 스크롤될 때 데이터가 컬럼 레이블 뒤로 비쳐 보이지 않도록 불투명 배경(`bg-slate-50 dark:bg-slate-900`)과 가로 스크롤 시의 premium rounded border-spacing을 기본 제공합니다.
  - **권한 기반 액션 제어:** `onEdit`, `onDelete` 콜백을 권한(Engineer/Manager)에 따라 조건부로 넘겨주면, 수정/삭제 버튼이 권한에 맞게 자동 노출 및 제어됩니다.

- **Props 명세:**
  ```javascript
  MasterDataGrid.propTypes = {
      data: PropTypes.array.isRequired,            // 그리드에 바인딩할 데이터 배열
      columnDefs: PropTypes.object.isRequired,      // 전체 컬럼 정의서 ({ key: { label, default } })
      sortConfig: PropTypes.object,                 // 정렬 설정 ({ key, direction: 'asc'|'desc' })
      onSort: PropTypes.func,                       // 컬럼 헤더 정렬 클릭 이벤트 핸들러
      onRowClick: PropTypes.func,                   // 행 클릭 이벤트 핸들러
      rowKey: PropTypes.string,                    // 데이터의 고유 Key 필드명 (기본값 'id')
      cellRenderer: PropTypes.object,               // 컬럼별 커스텀 렌더러 함수 맵 ({ [key]: (val, row) => ReactNode })
      onEdit: PropTypes.func,                       // 수정 액션 핸들러 (null 지정 시 수정 버튼 숨김)
      onDelete: PropTypes.func,                     // 삭제 액션 핸들러 (null 지정 시 삭제 버튼 숨김)
      sortableColumns: PropTypes.array             // 정렬을 허용할 컬럼 키 배열 (비어있으면 전체 정렬 허용)
  };
  ```

- **사용 예시:**
  ```javascript
  import MasterDataGrid from '../components/common/MasterDataGrid';

  // 1. 컬럼 정의
  const COLUMN_DEFS = {
      PartID: { label: 'Part ID', default: true },
      Name: { label: '부품명', default: true },
      Spec: { label: '규격', default: true },
      UnitPrice: { label: '단가', default: true },
      Lifecycle: { label: '상태', default: true }
  };

  // 2. 컴포넌트 렌더링
  <MasterDataGrid
      data={parts}
      columnDefs={COLUMN_DEFS}
      sortConfig={sortConfig}
      onSort={handleSort}
      onRowClick={(row) => handleRowClick(row)}
      sortableColumns={['PartID', 'Name', 'Spec', 'UnitPrice']}
      cellRenderer={{
          Lifecycle: (val) => (
              <span className={`px-2.5 py-0.5 rounded-full text-xs font-black ${val === 'Active' ? 'bg-emerald-100 text-emerald-700' : 'bg-red-100 text-red-700'}`}>
                  {val === 'Active' ? '양산' : '단종'}
              </span>
          ),
          UnitPrice: (val) => val ? `$${Number(val).toLocaleString()}` : '-'
      }}
      onEdit={hasPermission ? handleEdit : null}
      onDelete={hasPermission ? handleDelete : null}
  />
  ```

### 2.2. `<TransactionHistoryTable />` (수불 원장 테이블)
- **사용처:** 통합 입출고 원장 메인(2-17), 부품 상세 패널 내부 탭
- **주요 레이블 및 필드:**
  - `일시(Date)`, `트랜잭션 타입(In/Out/Adjust)`, `수량(+Qty / -Qty)`
  - `로케이션(From -> To)`, `참조 문서(PO 번호 또는 WO 번호)`, `작업자(User)`
- **핵심 기능:**
  - In(입고)은 푸른색(+), Out(출고)은 붉은색(-) 텍스트로 시각적 대비 효과 적용.
  - 무한 스크롤(Infinite Scroll) 적용으로 스크롤을 내릴 때마다 과거 데이터를 Lazy Loading.

## 3. 공통 모달 및 폼 (Modals & Forms)

### 3.1. `<EntityFormModal />` (동적 폼 모달)
- **주요 레이블 및 구성요소:**
  - 폼 헤더: `[엔티티명] 신규 등록 / 수정`
  - 필드 레이블: 필수 항목은 붉은색 `*` 별표 표시 (예: `부품명 *`)
  - 하단 버튼: `[취소(Cancel)]`, `[저장(Save)]`
- **핵심 기능:**
  - **유효성 검사(Validation):** 필수 값을 비우거나 포맷(이메일 등)이 틀릴 경우, 필드 하단에 붉은색 에러 메시지(예: *"이메일 형식이 올바르지 않습니다."*) 실시간 렌더링.

### 3.2. `<ApprovalLineSelector />` (전자결재 라인 지정 모달)
- **주요 레이블 및 필드:**
  - `기안자(Initiator)`, `1차 결재자(Reviewer)`, `최종 승인자(Approver)`
  - `결재 의견(Comment)` 텍스트 에어리어(Textarea).
- **핵심 기능:**
  - 사내 조직도 트리(Org Chart)를 띄워 부서별 담당자를 클릭하여 결재 라인에 드래그 앤 드롭 추가.

### 3.3. `<LocationSelectorModal />` (로케이션 지정 모달)
- **주요 레이블 및 필드:**
  - `선택된 위치 (예: MAIN-RACK-01-A)`
  - `현재 남은 적재 용량(Capacity)`
- **핵심 기능:**
  - 창고 > 랙(Rack) > 빈(Bin)으로 이어지는 3-Depth 트리 구조를 클릭하여 펼치고(Expand) 선택하는 기능.

## 4. UI 유틸리티 및 뱃지 (Utilities & Badges)

### 4.1. `<StatusBadge />` (상태 뱃지)
- **기능 및 시각적 레이블 맵핑:**
  - `[발주 중]` (ORDERED): 파란색 배경 + 흰색 텍스트
  - `[검사 대기]` (WAITING_INSPECTION): 노란색 배경 + 검은색 텍스트
  - `[합격/완료]` (COMPLETE/RECEIVED): 초록색 배경 + 흰색 텍스트
  - `[불합격/반품]` (REJECTED/RTV): 빨간색 배경 + 흰색 텍스트

### 4.2. `<UrgentIndicator />` (긴급 생산 뱃지)
- **기능:** 번개 ⚡ 아이콘과 함께 `[긴급 투입]` 붉은색 레이블이 1초 간격으로 점멸(Blinking CSS)하여 물류 담당자의 즉각적인 행동(빠른 적재 및 라인 투입)을 유도함.

## 5. 공통 필터 컨트롤 (Filters & Search)

### 5.1. `<SearchAndFilterBar />`
- **주요 필드 및 레이블:**
  - `검색어 입력... (부품명, ID 등)`
  - `[카테고리 선택 ▼]`, `[담당자 선택 ▼]` (다중 선택 체크박스 드롭다운)

## 6. 단일 목적형(특화) 컴포넌트 (Domain-Specific Components)
> 여러 페이지에서 중복 사용되지 않더라도, 해당 컴포넌트 자체가 가지는 로직(재귀 연산, Drag&Drop 등)이 무거워 메인 페이지 코드 가독성을 위해 격리해 낸 독립 컴포넌트입니다.

### 6.1. `<BOMTreeView />`
- **주요 레이블:** `[전체 펼치기(Expand All)]`, `[전체 접기(Collapse All)]`, `자재명`, `소요량`
- **핵심 기능:** 자기 자신을 계속 호출하는 재귀(Recursive) 렌더링 로직 적용. 각 노드 앞의 `[+] / [-]` 아이콘을 눌러 하위 자재를 열고 닫음.

### 6.2. `<KanbanBoardEngine />`
- **주요 레이블:** 보드 컬럼 헤더 (`대기(To-Do)`, `진행 중(In Progress)`, `완료(Done)`)
- **핵심 기능:** 카드를 마우스로 집어서(Drag) 다른 컬럼에 놓을 때(Drop), 백엔드에 상태 변경 API를 자동 트리거하고 화면을 낙관적 업데이트(Optimistic Update)로 즉각 반영함.

### 6.3. `<QADefectInputForm />` (QA 품질 검사 폼)
- **주요 레이블:** `외관 검사 (Pass/Fail)`, `치수 검사 (오차 범위 입력)`, `불량 사유(Defect Reason)`
- **핵심 기능:** `Fail` 선택 시, 하단에 불량 사유를 기입하는 텍스트박스와 불량 사진을 첨부하는 `<CommonFileUploader />`가 조건부(Conditional)로 등장함.

## 7. 데이터 수정 및 이력 관리 (Audit Trail) 전용 컴포넌트
> 공급사 마스터, 수불 내역, 품질 검사 등 원칙적으로 수정이 엄격히 통제되어야 하는 중요 데이터의 변경을 안전하게 처리하고, 그 변경 이력(누가, 언제, 왜 바꾸었는지)을 추적하기 위해 설계된 컴포넌트들입니다.

### 7.1. `<AuditTrailViewer />` (수정 내역 추적 타임라인)
- **사용처:** 공급사 상세 뷰(2-10), 입출고 원장 상세(2-17), QA 검사 히스토리(2-14)
- **주요 레이블:** `수정 일시`, `수정자(User)`, `변경 항목(Field)`, `변경 전(Before) → 변경 후(After)`, `수정 사유(Reason)`
- **핵심 기능:** 
  - 특정 엔티티에 대해 발생한 모든 데이터 수정 내역의 스냅샷을 타임라인(Timeline) 형태로 렌더링.
  - 변경 전/후의 데이터 차이(Diff)를 붉은색(-)과 푸른색(+) 텍스트로 시각적으로 강조하여 직관성을 높임.

### 7.2. `<TransactionCorrectionModal />` (수불장/입출고 내역 정정 모달)
- **사용처:** 통합 입출고 원장(2-17)
- **주요 레이블:** `원 거래 내역 표시`, `올바른 수량 기입란`, `정정 사유 선택 (예: 휴먼에러, 누락 등)`, `관리자 승인 비밀번호`
- **핵심 기능:**
  - 기존 수불 내역을 단순히 덮어쓰지 않고, 원본 거래를 무효화하는 '취소 전표(역분개, Reverse Transaction)'를 백그라운드에서 자동 발행한 뒤 올바른 수치로 새 전표를 등록하는 무결성 보장 로직 수행.

### 7.3. `<QAInspectionCorrectionModal />` (QA 품질 검수 결과 정정 모달)
- **사용처:** QA 검사 관리(2-14)
- **주요 레이블:** `기존 기입된 합격/불량 수량`, `변경할 정확한 수량`, `불량 사유 수정 내역`, `품질 책임자 결재 란`
- **핵심 기능:**
  - 작업자 실수로 합격 처리되어 이미 창고 적재(Placement)까지 넘어간 부품을 뒤늦게 불량으로 정정해야 할 경우, 창고 재고를 강제로 다시 차감하고 반품(RTV) 큐로 데이터를 즉시 돌려보내는 복잡한 복합 롤백(Rollback) 통제 로직 실행.
